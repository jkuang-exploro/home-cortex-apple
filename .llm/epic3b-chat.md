## Existing canonical path

Inspected `src/home_gui/src/lib/api.ts`, `App.svelte`, `components/Chat.svelte`, the conversation routes/dependencies/store, SSE renderer, and AnswerExecution. GUI uses its signed `/session` cookie, GET `/conversations` for summaries, POST `/conversations` with `{model, language}`, GET `/conversations/{id}` for a transcript, and POST `/conversations/{id}/messages` with `{content, stream:true}`. The create/history response is `object: conversation` with ID, model, runtime agent ID, entity ID, language, greeting, timestamps, null/selected active embodiment, and persisted messages `{id, role, content, created_at}`. Message submission returns canonical OpenAI-compatible `chat.completion.chunk` SSE deltas, a stop chunk, and `[DONE]`; errors are SSE error records. Greeting and personality originate on the server.

The actual runtime ID is `steward`, display name 老管家, entity `agent:butler`; these identities were verified rather than inventing an `agent:butler` route. The route calls the existing AgentService with the same identity resolver, transcript, planner, facts, tools, and LLM used by GUI. SurrealConversationStore owns durable history in dedicated GUI transcript tables, not household graph records. Conversation IDs are independent of V1 client and runtime-session IDs. Canonical message handling trims content on the backend; Swift sends the original text without trimming or translation.

There is no message request ID/idempotency key. Repeated POSTs append distinct turns. There is no separate cancellation endpoint: SSE client disconnect cancels execution; AnswerExecution closes its source and may persist a partial assistant answer. Native Stop uses that existing behavior, without inventing a cancellation operation.

## Authentication and backend changes

Added explicit `CORTEX_CALLER_IDENTITY_MAP` (default `{}`) as narrow application authorization: registered client ID maps to an existing household person. A verified TLS certificate alone has no conversation permission. The API reuses ClientInterfaceService.authenticate with only the proxy-verified certificate/private upstream secret, rejects DEVICE/PROVISIONER/body-bound/unmapped/disabled/revoked/expired credentials, requires the ordinary null-body session grant, and validates `X-Cortex-Session` as ACTIVE, software-only, and owned by that exact credential.

Permission covers only GET/POST `/conversations` list/create/read/message routes for the mapped person's null-body steward conversations. Bare models, other agents, foreign owners, existing body-bound transcripts, body selection, admin/model routes, and robot control are denied. Client/person headers cannot select identity; there is no bearer/cookie fallback for this principal. Existing GUI/bearer authentication and canonical semantics remain unchanged. No chat capability, Apple semantic branch, embodiment creation, or assignment modification was added.

The TLS 1.3 mTLS proxy on 8443 exposes canonical `/conversations`, substitutes only its verified certificate/private secret, strips bearer/cookie headers, disables buffering/cache, and allows the existing SSE stream. Bootstrap 8444 continues denying conversation access. Updated settings, Compose environment declaration/template, deployment docs, and regression tests.

Production maps the enrolled physical phone's specific client ID to the existing 匡健 person. Existing operator and device grants were not expanded. Production read-back confirmed the phone remains a null-body CALLER with exactly its session grant; consumed Mac/server invitation transfer files were removed. Built the new API image before recreating only cortex-api, preserved existing Compose content, saved owner-only deployment backups on the server, updated the generated proxy file in place to preserve its bind-mounted inode, ran nginx configuration validation, and reloaded nginx. Confirmed exact live mapping and production development-authentication disabled. Trusted TLS 1.3 discovery and bootstrap conversation denial passed after deployment.

## Native architecture and behavior

`Core/Conversation` defines canonical transcript/request decoding, bounded SSE framing, safe error categories, and an ephemeral URLSession transport sharing the existing original-CA/hostname/validity/client-identity TLS delegate. TLS 1.3, no redirects, cookies, cached credentials, legacy keys, or insecure fallback. History uses bounded streamed reads; SSE requires valid chunk identity, role/index/content shape, stop and `[DONE]`, with cancellation/size limits. Network timeout, unavailable backend, invalid response, conversation failure, authentication denial, and not-connected state have distinct safe messages. Remote exception prose is not displayed.

`ConversationController` runs on MainActor with explicit idle/loading/ready/sending/failed states and user pending/sent/failed plus assistant receiving/complete/failed states. Async generations fence cancelled/late responses. No automatic send retry occurs. A local preflight failure can retry safely; an uncertain submitted turn requires server-history reconciliation. Only the selected conversation ID is saved in UserDefaults, scoped to server/client; transcripts are loaded from Home Cortex. Reconnect/relaunch retains the selected ID independently of runtime-session changes, and uses the latest authorized steward thread if none is selected. Safe unsent local failures survive history refresh.

Root uses a shared native connection/chat model so hosted physical tests exercise the same state used by the screen. Provisioned clients open `ConversationView`: 老管家 heading, truthful V1 indicator, connection settings sheet, scrollable Unicode message bubbles, multiline composer, keyboard safe-area inset, send/Stop, failure details/reload, and scroll-to-latest. iPad uses the same implementation with a wider bounded reading column. Unprovisioned clients retain the original CA/invitation screen. Existing history remains visible offline; sending requires the actual valid ACTIVE session and loaded conversation. Background cancels an in-flight response; foreground reloads server truth after reconnect.
